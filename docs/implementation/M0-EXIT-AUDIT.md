# M0 Exit Audit

Status: **Complete on `impl/m0-workspace-foundation`**
Milestone: **M0 - Workspace and CI foundation**

This record audits the implementation branch against the M0 deliverables and exit gates in `docs/blueprint/17-IMPLEMENTATION-ROADMAP.md`.

## Deliverables

### Workspace

Implemented:

- root Cargo workspace using resolver 3;
- initial crates only: `osrs-core`, `osrs-cache`, `osrs-scene`, `osrs-reference`;
- Rust 2024 edition;
- pinned Rust 1.99.0 toolchain with `rustfmt` and Clippy;
- committed `Cargo.lock` generated by the pinned CI environment;
- workspace lint policy with `unsafe_code = "forbid"` and selected Clippy denials/warnings.

`osrs-render` and `osrs-editor` remain intentionally absent until their owning milestones.

### Architecture enforcement

Implemented `scripts/check_architecture.py` with tests that prove it rejects:

- production dependencies on `osrs-reference`;
- aliased production dependencies on `osrs-reference`;
- `osrs-scene -> osrs-cache`;
- renderer/UI/cache-transport dependencies in `osrs-core`;
- target-specific renderer dependency leakage;
- aliased renderer dependency leakage.

The checker also accepts the intended `osrs-reference -> osrs-core/osrs-cache/osrs-scene` tooling edges.

### CI Tier A

GitHub Actions enforces:

1. architecture checker;
2. architecture-checker unit tests;
3. `cargo fmt --all --check`;
4. `cargo check --locked --workspace --all-targets --all-features`;
5. `cargo clippy --locked --workspace --all-targets --all-features -- -D warnings`.

### CI Tier B

GitHub Actions runs:

`cargo test --locked --workspace --all-targets --all-features`

The locked Tier A and Tier B run completed successfully before this exit record was written.

### Fixture foundation

The canonical `reference-fixtures/` family layout now exists for:

- manifest;
- placement;
- model;
- normals;
- lighting;
- morph;
- animation;
- contour;
- terrain;
- planes;
- priority;
- alpha;
- textures;
- scenes;
- images.

`osrs-reference` contains the first versioned YAML manifest parser with typed validation for schema version, fixture ID, owning specs, parity level, oracle provenance, harness provenance, input/output paths, and expected SHA-256.

Parser tests prove valid manifests parse and malformed, unsupported-version, missing-spec, and invalid-hash manifests fail without panicking.

### Error/provenance conventions

`M0-ERROR-PROVENANCE-CONVENTIONS.md` establishes:

- layer-owned errors;
- external-data fallibility;
- cause/context preservation;
- structured provenance rather than log-only provenance;
- no shared mega-error enum;
- no premature M1/M2 target/profile semantic API.

## M0 non-goals preserved

M0 does not decide:

- the initial target/cache profile;
- whether `rs-cache` is wrapped, forked, partially reused, or replaced;
- final semantic ID/coordinate/definition APIs;
- cache transport/decoder implementations;
- scene placement/model semantics;
- renderer/editor crates.

Those remain owned by M1 and later milestones.

## Handoff to M1

M1 begins with the exact target-profile/cache-contract spike from the roadmap. It must make the cache dependency decision through a new ADR rather than treating the historical `rs-cache` recommendation as already accepted.
