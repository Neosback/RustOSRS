# M5 Model Fixture Migration Record v1

Status: `SOURCE_PINNED_MANUAL_NORMALIZATION`

This record is the deterministic migration/harness provenance for the first normalized M5 model fixtures.

These expected outputs are **not** claimed to have been generated by a Java/deob executable harness. They are normalized from the exact M4 semantic cases that were source-audited against the pinned public deob and already enforced by executable Rust equality tests. M5 Checkpoint 4 owns the later executable regeneration/oracle-adapter workflow.

## Normalization rules

- Inputs and expected outputs are UTF-8 JSON objects using normalized schema version `1`.
- Integer vertex order is preserved exactly.
- Face index order is preserved exactly.
- Model ID order is preserved exactly.
- No coordinate sorting, epsilon rounding, face reordering, default substitution, or renderer-space conversion is permitted.
- `null` remains distinct from an integer texture/model value.
- Expected-output SHA-256 is calculated over the exact checked-in bytes, including the final newline.

## Migrated cases

### `model.selection.typed_exact.orientation_4`

Source contract: `ObjectComposition.getModelData` typed-model exact match and `isRotated XOR (orientation > 3)` raw mirror selection.

M4 executable cross-check: `crates/osrs-core/src/model_construction.rs`, test `typed_selection_requires_exact_type_and_uses_xor_mirror_rule`.

### `model.mirror.geometry_winding`

Source contract: `ModelData.method5280` negates model-local Z and swaps face A/C winding.

M4 executable cross-check: `crates/osrs-core/src/model_construction.rs`, test `mirror_negates_z_and_reverses_face_winding_without_mutating_source`.

### `model.transform.type4_order`

Source contract: `ObjectComposition.getModelData` performs the loc-type-4 high-orientation 256-JAU rotation and `(45, 0, -45)` recenter before orientation masking, then quarter rotation, recolor, retexture, resize, and definition translation. `ModelData` supplies the integer transform operations and `Rasterizer3D` supplies the pinned trigonometric table behavior.

M4 executable cross-check: `crates/osrs-core/tests/m4_instance_transform.rs`, test `combined_type4_pipeline_is_order_exact_and_source_isolation_is_preserved`.

## Regeneration boundary

Changing a normalized input, expected output, source pin, or normalization rule requires review of the associated manifest and expected-output hash. Ordinary CI must consume these checked-in artifacts offline and must never rewrite them.
